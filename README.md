# Расклад

Расклад: веб-сервис для расчета роботизации склада, аэропорта или медучреждения. Он подбирает роботов из каталога, проверяет парк прогоном смены на плане и считает экономику внедрения.

Команда unicorn, хакатон "Лидеры цифровой трансформации 2026", задача №1.

[Стенд](https://rasklad-robots.ru) · [Запустить у себя](#быстрый-запуск) · [Документация](docs/documentation.md)

Вход на стенд по логину и паролю из README.txt в материалах сдачи на Яндекс.Диске.

![Шаг экономики: покупка 9 роботов Ronavi H1500 окупится за 1,3 года, под ответом смена на плане склада в пиковый час](docs/images/documentation/00-readme-answer-shift.png)

Объект → Параметры → План → Подбор роботов → Прогон смены → Экономика

Демо-результат на данных организатора: зона работы роботов 10 000 м2, 2 000 паллет в сутки → 9 роботов и 3 зарядки, 41,4 млн ₽ на старте, окупаемость покупки 1,3 года, за 5 лет дешевле, чем без роботов, на 137,2 млн ₽. Как повторить руками: [раздел 6.10 документации](docs/documentation.md#610-воспроизведение-демо-расчета).

## Цель

Дать проверяемый ответ на два вопроса: какие роботы подходят объекту и окупится ли их внедрение. Не рекламные цифры производителя, а расчет на данных клиента, где у каждой существенной цифры есть источник и оценка доверия.

## Для кого

- Руководитель склада: нужны цифры для решения.
- Финансист: проверяет расчет по формулам и источникам.
- Интегратор: прикидывает проект клиенту.
- Администратор ФЦ БАС: ведет каталог решений и нормативы.

## Что делает

Подбирает решение под задачу объекта, считает необходимый парк, первоначальные вложения и стоимость владения за 5 лет, и показывает, от каких цифр результат зависит сильнее всего. Отчет выгружается в PDF и Excel.

Человек описывает склад и работу, которую хочет отдать роботам, чертит или берет типовой план, выбирает решение из каталога, и сервис считает парк, вложения, окупаемость и стоимость владения для трех сценариев: без роботов, покупка и роботы как услуга. Сервис проверяет достаточность парка прогоном смены: роботы ездят по плану клиента, стоят в очередях и заряжаются.

Методика расчета, все формулы с примерами руками: [docs/calculation.md](docs/calculation.md).

## Что мы проработали сами

Пять тем, которые организатор попросил команды проработать самостоятельно (раздел 7 "Дополнений").

Подробно в разделе [Что мы прорабатывали сами](docs/documentation.md#что-мы-прорабатывали-сами).

1. [Исключение неподходящих решений](docs/documentation.md#1-условия-исключения-неподходящих-решений): задача, груз, проход, подъем, пандус, стеллажи; чего нет в источниках, то "требует проверки".
2. [CAPEX и OPEX покупки и услуги](docs/documentation.md#2-состав-capex-и-opex-для-сценариев-покупки-и-услуги): одни статьи в расчете, на экране и в отчете, сверены с легендой датасета.
3. [Допущения по неполным данным](docs/documentation.md#3-допущения-по-отсутствующим-или-неполным-данным): у каждой цифры источник и оценка, у слабых влияние на результат.
4. [Роботы как услуга](docs/documentation.md#4-логика-экономической-модели-роботы-как-услуга): разовый платеж, плата в месяц, порча, выкуп по остаточной стоимости, платежи по годам.
5. [Расширение каталога](docs/documentation.md#5-расширение-каталога-и-работа-с-открытыми-источниками): 31 решение склада с характеристиками, 12 для аэропорта, 18 для больницы, около 1 600 значений со ссылками.

## Ограничения и что делаем дальше

### Ограничения текущей версии

- Аэропорт и медучреждение доходят до параметров и списка решений с объяснением, без плана, прогона смены и экономики. Расчет для них еще нужно оценить и проверить на реальных внедрениях, как мы сделали для склада.
- В подборе нет правил ровности пола, температуры, лифтов и WMS: этих полей нет в каталоге.
- Живой интеграции с WMS и 1С нет, вместо нее импорт выгрузок и API.
- Список задач объекта пока в коде.
- Остальные ограничения расчета: [документация, раздел 6.9](docs/documentation.md#69-известные-ограничения-и-план-развития).

### Что делаем дальше

- Аэропорт и медучреждение полным путем, как склад: план, прогон смены, экономика, отчеты. Работу мы начали в отдельной ветке, готово примерно наполовину, в эту версию не включили.
- Чертеж склада: обновляем по отзывам тестировщиков, понятнее инструменты и обучение, меньше ручной работы.
- Английский язык интерфейса, перевозка коробов, больше двух решений на задачу, коннекторы к 1С и WMS.
- Исследование пользователей: к следующей версии соберем материалы опросов и интервью с руководителями складов и интеграторами и выложим их вместе с материалами сдачи.

## Быстрый запуск

Нужен Docker.

```bash
cp .env.example .env
docker compose up --build
```

- интерфейс: http://localhost:3000, расчет без входа: http://localhost:3000/calc, вход: http://localhost:3000/login
- как мы считаем, методика картинками: http://localhost:3000/method
- описание API: http://localhost:8000/api/docs, служебные таблицы администратора: http://localhost:8000/api/db

Файлов организатора хакатона (выгрузки каталога, фото и датасета) здесь нет: по условию их нельзя публиковать. В открытой версии 31 складское решение с характеристиками, которые мы собрали с сайтов производителей, при первом запуске они ложатся в базу из `data/specs`. Сервис работает сразу. Демо-расчет из документации воспроизводится на открытом каталоге из 31 решения: Ronavi H1500 входит в него. Полный каталог организатора, 190 позиций, загружается администратором из материалов сдачи, см. ниже.

Вернуть демо-проекты и каталог в исходный вид: `docker compose exec backend python -m scripts.reset_demo`.

Для регистрации подойдет любая почта вида `ivan@example.com`, настоящую вводить не нужно: письма мы не шлем, а почту видит администратор сервиса.

Стенд в интернете поднимается другой командой, с https, паролем на весь сайт и выключенным демо-входом: [docs/stand.md](docs/stand.md).

Файлы организатора и наш дополненный каталог лежат в материалах сдачи на Яндекс.Диске, которые передаются вместе с проектом.

### Полный каталог из материалов сдачи

Полный каталог (190 позиций, с фото и данными организатора) в открытой версии не публикуем по условию организатора хакатона. Проверить его можно двумя способами:

1. Открыть стенд https://rasklad-robots.ru: он собран из закрытого репозитория, каталог там уже полный.
2. Поднять сервис локально из этого репозитория и загрузить каталог самому: войти администратором, открыть `/admin`, в разделе "Каталог решений" нажать "Загрузить выгрузку" и выбрать файл `catalog_export_v4.csv` из материалов сдачи на Яндекс.Диске.

Порты и демо-пароли. Если порты 3000 или 8000 заняты, задайте другие в `.env`: `FRONTEND_PORT=3001`, `BACKEND_PORT=8001`. При запуске создаются два демо-аккаунта: пользователь `demo@example.com` с паролем `demo12345` и администратор `admin@example.com` с паролем `admin12345`, вход по почте и паролю на обычном экране входа; почты и пароли меняются в `.env`. Эти пароли и быстрый вход в демо (`DEMO_LOGIN=true`) действуют только при запуске у себя; на стенде быстрый вход выключен, пароли свои.

Если Docker Desktop не запускается: [инструкция по запуску через WSL](docs/troubleshooting.md).

## Что попробовать за 10 минут

1. Без входа: "Посчитать свой склад", пройти пять шагов, поменять объем или план, скачать PDF.
2. Зарегистрироваться, сохранить расчет, в кабинете сделать копию "что будет, если" и сравнить с оригиналом. Вернуться на главную: там план вашего склада.
3. На шаге 4 добавить к задаче второго робота или задать бюджет, на шаге 5 включить кредит или лизинг.
4. Войти демо-администратором: главная администратора, каталог деревом, раздел "Нормативы", "Проверить обновления".
5. Открыть "Как мы считаем" (/method): путь расчета, парк, сценарии, окупаемость, шкала доверия S-F.

Подробный сценарий на 14 шагов: [приложение Б документации](docs/documentation.md#приложение-б-демо-данные-и-сценарий-проверки-основных-функций).

### Кабинет и администрирование

- Кабинет: главная с последним проектом, проекты с версиями и папками, сравнение рядом, копия "что будет, если", ссылка "поделиться", профиль, темная тема.
- Администратор: своя главная с графиками и журналом правок, каталог решений (список или дерево, выгрузка и загрузка файлом, 31 позиция в открытой версии, 190 с выгрузкой организатора), нормативы, проверка обновлений характеристик на сайтах производителей.

## Разработка без Docker

Требования: Python 3.12, Node.js 24.

Бэкенд:

```bash
cd backend
pip install -e ".[dev]"
pytest
uvicorn app.main:app --reload
```

Фронтенд:

```bash
cd frontend
npm install
npm run dev
```
