# Требования ТЗ

Собрали в один список требования ТЗ, дополнений для участников и данные организатора, чтобы отмечать что уже сделали.

Приоритет: M обязательно, S желательно, B дает дополнительные баллы по критериям оценки.

## Критерии оценки

| Критерий | Вес |
|---|---|
| Техническая проработка (архитектура, запуск, модель данных, стабильность) | 25% |
| Соответствие задаче (путь, каталог, подбор, расчет, сравнение, визуализация, сохранение, экспорт) | 25% |
| Эффективность (обоснованность расчетов, объяснимость, ценность, визуализация, масштабируемость) | 25% |
| Подход команды (понимание, границы MVP, допущения) | 15% |
| Питч | 10% |

Дополнительные преимущества: автообновление каталога, оптимизация или машинное обучение при обоснованной задаче, интеграционные API, расширенная чувствительность, детальная модель нескольких объектов, качественное происхождение данных.

### Экономика
- [x] M · Количество роботов = пиковая потребность / эффективная производительность * загрузка, доступность, резерв (формула рядом с прогоном смены)
- [x] M · CAPEX: оборудование + инфраструктура + ПО + интеграция + пусконаладка + обучение + резерв
- [x] M · OPEX: сервис + лицензии + энергия + связь + расходники + ремонт + персонал эксплуатации (расходники как у организатора: замена АКБ, см. calculation.md, раздел 4)
- [x] M · Годовой эффект, простой срок окупаемости, ROI, TCO >= 5 лет с заменой АКБ (и NPV, IRR)
- [x] M · Амортизация (линейная, срок службы в допущениях)
- [x] M · Сценарии: без роботизации / покупка / RaaS в одной таблице
- [x] M · Чувствительность >= 3 параметров для каждого сценария ("что будет, если", все числа по силе влияния)
- [x] M · Пользователь меняет: стоимость персонала, режим, производительность, стоимость оборудования и обслуживания, загрузку, горизонт
- [x] M · Автоматические значения можно поправить вручную, изменение фиксируется
- [x] M · Вывод не по жесткому порогу: число + интервал (до 3 / 3–5 / более 5 лет) + риски + интерпретация
- [x] M · Формулы, единицы, источники, допущения видны в интерфейсе или отчете (и страница "Как мы считаем", /method)

## Данные организатора

- `catalog_export_v4.csv`: 223 решения, 147 БРС, 72 БАС, 4 ПО. Поля: название, тип, статус (эксплуатация/пилот/разработка), компания, описание, тип/подтип, сценарий, кейсы, УГТ, рыночный потенциал, регион, отрасль, цена. ТТХ нет. Цены с НДС, без доставки, пусконаладки и интеграции; дубли с одинаковой ценой по ответу организаторов объединяем ([вопросы организаторам](questions.md)).
- В дополнениях к ТЗ (п. 6) файл с ценами назван `catalog_export_v5`, а у нас есть только `catalog_export_v4.csv`. Нужно уточнить у организатора, выдавали ли v5. Если да, загружаем его в админке поверх v4: ручные правки сохранятся, отчет загрузки покажет, что поменялось.
- Для склада в каталоге 31 подходящее решение: AMR, FMR, штабелеры, тягачи, автоматические склады, шаттлы, SmartCube, манипуляторы, инвентаризаторы, уборщики. Как отбирали, описано в [журнале решений](decisions.md). Для аэропорта решений мало: тягач Cognitive Pilot, EVOCARGO N1, уборщики, охранные роботы. Для медучереждения почти ничего нет, только дрон "Курьер-30" для доставки биоматериалов, а в примерах организатора PuduBot 2 и Ronavi SD.
- `Датасеты_хакатон.xlsx`: три листа объектов с базовым значением, min, max и источником. Ключевые нормативы из легенды: начисления на ФОТ 30,2%, резерв на пик 15–20%, загрузка AMR 70–85%, резерв CAPEX 10%, замена АКБ раз в 3–5 лет.
- `Примеры_решений_типы_объектов.docx`: характеристики примеров (H1500, DMR Carrier P, MARK 2 SE, Pallet Shuttle, Cognitive Pilot, EVOCARGO N1, Ronavi SD, PuduBot 2) и список открытых источников.
