# Стенд в интернете

Как поднять сервис по ссылке для экспертов. Для запуска у себя это не нужно, хватает `docker compose up` из README.

Чем стенд отличается от запуска у себя:

- перед сайтом стоит Caddy. Он сам получает и продлевает сертификат https, а http переводит на https;
- на весь сайт пускаем только по логину и паролю. Организатор разрешил показывать свои файлы (фото и каталог) только закрыто, поэтому посторонний не должен видеть даже лендинг. Логин и пароль стенда пишем в документации для экспертов вместе с демо-учетками;
- вход в демо-аккаунты без пароля выключен, cookie ходит только по https. Это задано в `docker-compose.stand.yml`, а не в `.env`, поэтому случайно включить нельзя;
- без своих паролей и ключа стенд не запустится: compose остановится и скажет, какой строки в `.env` не хватает.

## Что нужно

- Сервер в российском облаке: Ubuntu 24.04, 2 ядра, 4 ГБ памяти, 30 ГБ диска. Почта пользователей по 152-ФЗ должна храниться в России.
- Домен и запись A у регистратора: домен указывает на адрес сервера. Без домена сертификат https не выдадут.
- Открытые порты 22, 80 и 443. Остальные закрыть в панели облака.

## Первый запуск

На сервере:

```bash
curl -fsSL https://get.docker.com | sh
git clone git@github.com:ydrzml/unicorn-lct.git
cd unicorn-lct
cp .env.example .env
```

Репозиторий закрытый, поэтому серверу нужен ключ только на чтение: `ssh-keygen -t ed25519`, открытую часть (`~/.ssh/id_ed25519.pub`) добавить в настройках репозитория, раздел Deploy keys, без права записи.

В `.env` заменить значения из раздела "Для стенда". Ключ и пароли генерируем, а не придумываем:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

Эта команда дает `SESSION_SECRET`, `POSTGRES_PASSWORD` и пароли демо-аккаунтов. Пароль на весь сайт храним только как хеш:

```bash
docker run --rm caddy:2.10-alpine caddy hash-password --plaintext 'пароль для экспертов'
```

Результат вставить в `SITE_PASSWORD_HASH` в одинарных кавычках, иначе compose примет знаки `$` в хеше за свои переменные.

Запуск:

```bash
docker compose -f docker-compose.yml -f docker-compose.stand.yml up -d --build
```

Через минуту открыть `https://<домен>`: браузер спросит логин и пароль стенда, потом откроется лендинг. Если сертификата нет, смотреть `docker compose -f docker-compose.yml -f docker-compose.stand.yml logs caddy`. Чаще всего запись A еще не разошлась или закрыт порт 80.

В инструкцию для экспертов добавить строку: для регистрации подойдет любая почта, настоящую вводить не нужно. Демо-администратор на стенде общий, и в служебных таблицах он видит почты всех, кто зарегистрировался.

После запуска в каталоге наши 31 складское решение. Выгрузку организатора администратор загружает файлом в админке (раздел "Каталог решений", кнопка "Загрузить выгрузку"), после этого в каталоге 190 позиций. Новую версию выгрузки администратор может загрузить так же, повторным файлом.

## Обслуживание

Все команды из папки `unicorn-lct`, для краткости `STAND="-f docker-compose.yml -f docker-compose.stand.yml"`.

- Обновить до свежего кода: `git pull && docker compose $STAND up -d --build`.
- Вернуть демо-данные, если эксперт что-то поменял: `docker compose $STAND exec backend python -m scripts.reset_demo`. Проекты демо-аккаунтов удаляются, каталог становится как после первого запуска. Аккаунты, которые люди завели сами, не трогаются.
- Сменить пароль демо-аккаунта: поменять в `.env` и перезапустить `docker compose $STAND up -d`. Пароль сменится и у готового аккаунта.
- Остановить стенд: `docker compose $STAND down`. База остается на диске. С ключом `-v` удалится и она.
