# Границы MVP и риски

Что к финальной сдаче работает, что работает частично, чего еще нет и что может пойти не так. Обновляем по ходу.

## Что работает целиком

- Сквозной путь для склада из пяти шагов: объект и задачи, параметры, план склада, решение на каждую задачу, экономика трех сценариев. Несколько задач считаются одним объектом.
- План склада: чертеж на весь экран с обучением, шаблоны потока, план по фото, контур здания, ряды, ворота, уровни пола, проверки плана.
- Подбор по каталогу из базы: решения, подтвержденные для объекта, проверка процесса, грузоподъемности, ширины прохода, высоты подъема, пандусов и типа стеллажей, три группы выдачи, объяснимый балл, фильтры, поиск, сортировка и сравнение. На задачу можно взять два решения с долей объема. Бюджет на старте показывает, сколько роботов в него влезает.
- Экономика по ТЗ: количество роботов, CAPEX с резервом, OPEX по статьям, годовой эффект, простая окупаемость, ROI двумя цифрами, TCO за горизонт, амортизация, замена АКБ, вывод интервалом с рисками.
- Три сценария: без роботизации, покупка, роботы как услуга с выкупом по остаточной стоимости или продлением.
- Два режима эффекта: людей меньше при том же объеме и тот же штат при большем объеме.
- Ручная правка любого значения модели: правка уходит в расчет и возвращается в ответе (ТЗ, п. 3.5.4).
- Источник и оценка доверия от S до F у каждого значения, и это видно в интерфейсе.
- Расчет только на сервере, интерфейс показывает готовый результат.
- Прогон смены на плане клиента: маршруты, очереди в проездах и у ворот, зарядка, KPI, узкое место, проигрыватель со скоростями и шкалой, кадр PNG и журнал событий CSV. Парк берется по прогону, формула стоит рядом проверкой.
- Кредит и лизинг ползунками суммы, ставки и срока, меры господдержки, выход на режим, NPV и IRR, "что будет, если" по силе влияния, итог по каждой задаче. Блоки шага экономики списком строк с главными числами, раскрываются кнопкой "Подробнее".
- Закрытые вакансии в деньги не идут: "без роботов" и экономия считаются только по занятым ставкам.
- Проекты: сохранение с версиями, папки, копия "что будет, если", сравнение проектов, ссылка на версию только для просмотра, профиль. Отчет PDF и таблицы Excel.
- Роли гость, пользователь, администратор. У вошедшего и у администратора свои главные экраны.
- Админка: каталог 190 позиций из коробки, правка характеристик с источниками и журналом, дерево каталога, загрузка и выгрузка файлом, нормативы, проверка обновлений на сайтах производителей, служебные таблицы.
- Страница "Как мы считаем" картинками, темная тема.
- Запуск одной командой через docker compose, OpenAPI, типы фронтенда из описания API.
- Стенд https://rasklad-robots.ru: https, общий логин и пароль на весь сайт, демо-вход кнопками выключен. Логин и пароль стенда и демо-аккаунтов в материалах сдачи, в репозитории их нет.

## Что работает частично

| Что | Что есть | Чего не хватает |
|---|---|---|
| Каталог | 190 позиций, у 31 складского решения характеристики с источниками и оценками | У остальных позиций организатора характеристик нет, они ждут подтверждения задач в админке |
| Экономика решений | 21 робот склада с расчетными параметрами в модели | Решение без робота в модели в подборе видно, но помечено "не считается" |
| Объекты | Склад полностью | Аэропорт и медучреждение доходят до параметров и списка решений с объяснением, плана и экономики у них нет; что делаем дальше, экран говорит блоком "Что дальше" |
| Правила подбора | Грузоподъемность, проходы, подъем, пандусы, тип стеллажей, бюджет | Ровности пола, температуры, лифтов и наличия WMS в каталоге нет |

## Чего еще нет

- Публичной страницы каталога для гостя: гость видит решения на шаге подбора.
- Живой интеграции с WMS и 1С: вместо нее импорт Excel-выгрузок и API приема данных.
- Плана и прогона смены для аэропорта и медучреждения.

## Риски

| Риск | Чем грозит | Что делаем |
|---|---|---|
| 196 значений модели из 576 имеют оценку E или F, в демо-расчете 26 из 75 | Цифры экономики могут сдвинуться | Все они собраны в одном конфиге с источниками, меняются без правки кода, самые важные названы в методике |
| Производительность робота по формуле выше, чем на реальном внедрении | Парк занижен, окупаемость выглядит лучше | Появился прогон смены с очередями и зарядкой: на нем парк выходит больше. Разрыв с кейсом Восток-Сервиса остается, в прогоне пока нет станций комплектации |
| Данные организатора не сходятся между собой | Легко посчитать неверно и не заметить | Проверки записаны в правилах данных, в расчет берем осторожный вариант |
| Не у всех решений каталога есть параметры для экономики | Часть решений только в подборе | Показываем честно пометкой "не считается", расчетные параметры добавляются в модель с источником |
| Мало времени до финала, часть команды по два часа в день | Часть функций может не успеть | Держим границы MVP в этом файле и режем по приоритетам ТЗ |
| Цена аренды одна и та же с 2019 года | Сценарий аренды может быть неточным | Отдельный параметр, проверили обратным счетом на кейсе: с окупаемостью за 6 месяцев сходится |

## Как проверить своими руками

```bash
cp .env.example .env
docker compose up --build
```

1. Открыть http://localhost:3000, "Посчитать свой склад", оставить склад и перевозку паллет.
2. На шаге параметров поменять зарплату оператора погрузчика или объем.
3. На шаге плана пройти обучение или взять шаблон.
4. На шаге решения сравнить два решения, выбрать Ronavi H1500, при желании задать бюджет.
5. На шаге экономики посмотреть смену на плане, у строки "Откуда цифры" нажать "Подробнее", в "Чем платить" выбрать кредит, скачать PDF.
6. Войти демо-администратором: главная администратора, каталог, "Проверить обновления".

Описание API и все поля ответа: http://localhost:8000/api/docs.
