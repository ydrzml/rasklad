# Характеристики решений

В каталоге организатора нет технических характеристик роботов, поэтому мы собрали их из открытых источников. Как собирали и оценивали, описано в [data-sources.md](../../docs/data-sources.md).

## Файлы

| Файл | Что внутри |
|---|---|
| `sources.csv` | Все найденные значения. Одна строка: одно значение из одного источника, со ссылкой, цитатой и датой |
| `specs.csv` | Итог по каждой характеристике: оценка, значение для расчета и все варианты, которые нашли |
| `analogs.csv` | Отраслевые цифры и похожие модели для расчетной модели: батареи, цены батарей, ПО, обслуживание, аренда уборщиков. Одна строка: одно значение из одного источника |
| `catalog_marks.csv` | Отметки "Протестировано ФЦ БАС" и "Есть в 719" с карточек PDF-каталога, в CSV каталога их нет |
| `rate_specs.py` | Пересчитывает `specs.csv` из `sources.csv` и переносит значения с оценками в `data/catalog/warehouse.csv` |
| `catalog_marks.py` | Достает отметки из PDF-каталога |
| `saved/` | Строки характеристик трех страниц производителей для проверки обновлений без интернета, сохраняет `python -m scripts.save_spec_pages` из backend |

GitHub показывает CSV как таблицу с поиском. Для скрипта с PDF нужен `pip install -r data/specs/requirements.txt`.

```bash
python data/specs/rate_specs.py
```

## Какие решения взяли

Из 223 позиций каталога мы взяли 31. Это решения которые подходят для склада и которые уже можно заказать:

1. Взяли позиции со сценарием "Внутрискладская логистика", "Сортировка грузов", "Инвентаризация склада" или "Уборка помещений". Получилось 36.
2. Убрали 4 позиции в статусе "разработка", их пока нельзя купить.
3. Убрали Pick by Voice, это програма без оборудования.

Остальные позиции каталога из других отрослей, в расчете склада они не участвуют.

Для аэропорта и медучреждения добавили еще 20 решений: 6 из каталога и 14 из открытых источников. Список и причины в [data/facilities/solutions.csv](../facilities/solutions.csv). У решений не из каталога номер вида `ext-название`.

## Что получилось

| Оценка | Сколько характеристик |
|---|---|
| S, эталон | 0 |
| A, проверено | 36 |
| B, подтверждено | 28 |
| C, один источник | 183 |
| D, слабо | 65 |
| E, спорно | 22 |
| F, нет данных | 113 |

Всего 51 решение и 447 характеристик. Правила оценки и выбора значения для расчета в [правилах данных](../../docs/data-sources.md), разделы 2 и 4. Коротко: при споре в расчет идет значение организатора, а если актуальная страница производителя дает хуже, то оно.

Оценку A дает совпадение организатора и производителя. Оценки S нет: для нее нужен еще эксплуатант или независимая проверка, а такие источники с теми же цифрами мы пока не нашли. У 9 решений склада есть отметка "Протестировано ФЦ БАС", по ответу организатора она подтверждает работоспособность, а не цифры, поэтому оценку не повышает. У 6 решений отметка "Есть в 719", это реестр российской промышленной продукции.

Если источники расходятся, но мы поняли почему (другой режим, другая модель), это записано в примечании, оценка остается E. Удаленные страницы и прежние версии моделей отмечены в колонке `current` как "устарело" и в сравнении не участвуют. Значения похожих моделей отмечены "аналог": они тоже не сравниваются, а в расчет идут, только если у самого решения значения нет, с оценкой D. Среднюю скорость и теоретическую производительность вынесли в отдельные поля `avg_speed_m_s` и `throughput_theoretical`. Где характеристика к решению не относится (грузоподъемность у уборщика, ширина проезда у дрона), стоит "н/п".

`data/catalog/warehouse.csv` берет значения и оценки из `specs.csv`, скрипт переносит их сам. Сервис читает каталог из базы, а эти файлы заполняют ее при первом запуске. На Windows он пишет файлы с переводом строки CRLF, перед коммитом его надо вернуть к LF.
